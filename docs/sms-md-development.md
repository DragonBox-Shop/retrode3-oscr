# Sega Master System SMS-0007: Retrode3 v3 experimental read-only core

Status: **mock tested, physical cartridge not tested**. Intended for the
Retrode2 SMS-0007 passive MegaDrive-to-SMS adapter and Retrode3 2.9.5.
Requires the separately installed Linux 7.3 `retrode3.ko` driver with fixed
D0..D7 adapter mode 20 (`retrode3-kernel/develop` changes). The user has
already tested MegaDrive with this updated driver. No kernel or DTB update
is included here.

## Source of truth and deterministic OSCR generation

The SMS `.so` now compiles **pinned Sanni-derived code generated by** `tools/build-linux-sms-core.py`. This generator consumes the unchanged `third_party/oscr-firmware/src/cores/SMS.cpp` source, validates its Git blob and rejects all unreviewed upstream edits. It extracts Sanni's size switch and actual readROM bank/buffer loops, with narrowly audited Linux HAL substitutions. See [SMS generator architecture](sms-oscr-generator.md). The previous independent C++ `stream_rom` algorithm has been removed.

## Physical routing (authoritative: user's SMS-0007.sch and SMS-0007.brd)

| MegaDrive edge | SMS connector | Meaning in this core |
|---|---|---|
| D0-D7 | D0-D7 | 8-bit read path, kernel mode 20 |
| A1-A15 | A0-A14 | SMS byte address shifted left by one |
| A16 | A15 and /M0-7 | Low addresses enable first 32 KiB |
| A17 | /MC-F | Set high, prevent RAM selection |
| A18 | /M8-B | High below $8000, low for $8000-$BFFF |
| A22 | /WR | Set high (inactive) before selecting /CE |
| A23 | /RD | Keep low (active) for reads |
| OE and CE | /CE (same net) | Kernel selects slot and pulses OE |
| VCC | VCC plus SMS /RESET | **5 V required**, no level conversion on the adapter |

SMS-0007 schematic also connects the unpopulated Game Gear footprint to
D8-D15, not to the SMS data pins. GG is a separate future core. The adapter
itself contains no active bus transceivers, voltage regulator, or mapper.

The complete MD slot address used by the 7.3 fixed-lane reader is:

    physical_address = A22(1) | A23(0) | A17(1) |
        (cpu_address < $8000 ? A18(1) : A18(0)) | (cpu_address << 1)
    /dev/slot-md offset = (20 << 24) | physical_address

The complete physical address must stay below the MD slot's 23-bit limit.
Userspace uses `open(O_RDONLY)`, `lseek` and `read`; there is **no write(2)**
call to `/dev/slot-md`, no `/dev/mem`, no GPIO poking, and no voltage change.
Read windows never cross $8000 or $C000 boundaries. Because the MD port's
physical A0 does not address the SMS cartridge, each logical 512-byte
read samples 1024 consecutive MD positions and keeps the even-indexed
bytes. This is done in the POSIX transport, not in Sanni's ROM loop.

## Adapter bus sequencing and hot swap

SMS-0007 connects MegaDrive A22 to SMS /WR and A23 to SMS /RD.
The paired `retrode3-kernel/develop` fix prepositions the full
address, including A21 high (/WR inactive), while /CE is still inactive.
Only then is the slot selected. Both fixed 8-bit adapter modes get this
sequence, while normal SNES/MD/NES reads retain their existing logic.
The new adapter read loop also checks the cartridge sense line to stop
streaming if the cartridge is removed.

The Retrode3 is designed for cartridge exchange while powered on.
Slot sense events already exist, and MD removal returns VCC to 3.3 V.
**3.3 V is not power-off**. The generic CLI's event cancellation,
cross-core autodetection and voltage policy are being implemented
separately, not in this SMS module.

The initial header probe works at 3.3 V without an operator opt-in.
The ROM dump still requires confirmed 5 V and an explicit opt-in;
the SMS core itself never changes voltage. No writes to mapper, SRAM
or flash are enabled. Oscilloscope confirmation of /WR, /CE, /RD
timing and hot-swap electrical behavior is required before considering
this hardware-safe or promoting changes to master.

## Capability and opt-in boundary

- Core ID `sms-md`, physical slot `md`, generic NDJSON-v1 / ABI-v3.
- Linear ROMs **8, 16, 32 KiB** may be dumped experimentally.
- Sega-16-KiB mapper/banked ROMs 48 KiB..1 MiB have pure/mock-tested
  algorithms but live register writes are **rejected**.
- No SRAM/EEPROM/flash access, no cartridge register writes or auto-enabling.
- 3 bounded 16-byte reads at $1FF0, $3FF0, $7FF0 recognize `TMR SEGA` for a
  ROM-size *hint*. There is no title database, and final ROM is reported as
  `verification.status=not_checked`, `verified=false` until external CRC check.
- `fast_probe` is read-only and may inspect the header at 3.3 V
  without `RETRODE3_SMS_MD_EXPERIMENT`. The response includes
  `header_found` and `system_detected`; the latter is true only for
  an unambiguous `TMR SEGA` signature. No system is inferred from slot sense.
- The capability JSON exposes `probe_voltage_mv: 3300` and
  `read_voltage_mv: 5000` for generic CLI orchestration.
- The exact experimental opt-in **for ROM reading only** is:

    RETRODE3_SMS_MD_EXPERIMENT=enable-readonly-v1

The environment variable unlocks *only* the read-only linear path. It cannot
unlock bank writes or skip the VCC verification. It has no effect on other
cores. This is a deliberate first-lab feature, not general release support.

## Build, test and install on retrode3-oscr/develop

Run from a clean repository checkout on the Retrode3:

    git submodule update --init third_party/oscr-firmware
    make -f Makefile.migration test-sms-md-module

This invokes the strict upstream converter and tests its reproducibility and
failure on unexpected OSCR changes. The target builds `sms-md.so` only,
without rebuilding the shared CLI. The original submodule remains pristine.
Install the `sms-md.so` and matching `sms-md.core` pair manually to
`/usr/lib/retrode3/cores-available/` and enable only after reviewing the
hardware restrictions below. Do not add this lab core to default production
staging or `master`.

## Explicit experimental CLI workflow

The intended sequence is hot-swap at 3.3 V, plugin-owned read-only
header probe, generic CLI-selected 5 V only after identifying the system,
then the ROM dump. The CLI voltage controller is being implemented in a
separate change. Until it is integrated, use only an operator-approved lab
procedure for raising VCC. Never test SMS on a kernel without the
preselect fix and verified /WR timing.

For the manual CLI lab test, start the shared interactive CLI with
`RETRODE3_SMS_MD_EXPERIMENT=enable-readonly-v1`; this permits only
a 5 V ROM dump, not mapper or save writes:

    RETRODE3_SMS_MD_EXPERIMENT=enable-readonly-v1 \
      /usr/bin/retrode3-cli --protocol ndjson-v1 --interactive

Input lines (one JSON object per line):

    {"command":"get_capabilities","core":"sms-md","request_id":"cap"}
    {"command":"probe","core":"sms-md","request_id":"probe"}
    {"command":"read_rom","core":"sms-md","request_id":"rom32","output":"/tmp/sms-test.sms","selection":{"version":1,"mode":"override","schema_id":"sms-md-layout-v1","parameters":{"mapping":"linear","rom_kib":32}}}

Probe may yield `read_layouts:[{"id":"linear-32",...}]` where a valid
SMS header declares 32 KiB. A smaller header may represent a larger ROM:
verify the PCB and use an explicitly chosen safe ROM size. CRC matching
against a separate known-good image is needed before calling a dump correct.
If no 5 V is present or ROM read opt-in is missing, the full read is denied.
The 3.3 V header probe remains available. Failed reads must
never publish partial output via the common CLI.

## Validation

Generated Sanni bank/size algorithms, ABI-v3 callbacks, mocked kernel
transport, cancellation and CRC-facing output are tested in CI, including a
GCC 8 build. These are **not** physical-cartridge electrical acceptance tests.
The paired kernel preselect patch must first be built for the running kernel
and /WR versus /CE timing validated electrically.
